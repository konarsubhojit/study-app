# 8. Room is the local source of truth with explicit migrations

- Status: accepted
- Date: 2026-09-16

## Context

Timer events, tasks and uploads must survive process death and work offline. Their domain types live
in the Android-free `:core:model`, while persistence necessarily uses Android Room. A naive schema
can also regress invisibly: an unindexed list query works with ten rows, destructive fallback erases
the only offline copy after an upgrade, and storing local task times as instants shifts the user's
09:00 reminder across travel or daylight-saving changes.

## Decision

`:core:database` owns a Room database and maps to `:core:model`; Room annotations never enter the
domain module.

- Subjects, folders, materials and task reminders are normalized tables with foreign keys.
- A study session table stores metadata only. `session_events` is the source of truth and has a
  unique `(session_id, sequence)` index; status and elapsed time remain projections of the ordered
  event log as required by [ADR 0003](0003-timer-event-sourcing.md).
- DAO list reads return `Flow<List<...>>` with deterministic ordering. Indices cover folder material
  timelines, upload-state scans, task due-time scans and session-event folds.
- Task/reminder replacement, session creation and synthetic seeding are transactions. A failed child
  write cannot leave a partial aggregate.
- Absolute `Instant` values are signed UTC epoch milliseconds. Local task due times remain ISO local
  date-times with a separate IANA time-zone id, so persistence does not silently change wall-clock
  semantics.

`StudyFlowDatabaseFactory` registers every migration. Missing migrations fail by default. A caller
may request destructive fallback only for development, and the factory checks Android's installed
`FLAG_DEBUGGABLE`; a non-debuggable/release APK cannot enable it through a mistaken argument.

Room compiler schema exports under `core/database/schemas` are source-controlled. Version 1 is the
baseline; version 2 adds encrypted-material state and covering index refinements through
`MIGRATION_1_2`. Every future version must add an adjacent migration and a semantic migration test.
The registry continuity test fails if any shipped version is skipped.

Two deterministic synthetic profiles are provided:

- `DEVELOPMENT` is small enough for manual feature work.
- `PERFORMANCE` supplies realistic cardinalities for benchmark and query-plan validation.

Seeding is explicit, transactional and accepted only when all aggregate tables are empty. It is not
attached to production database creation.

## Validation

Fast JVM tests use Robolectric API 34 and a real in-memory Room database. They cover Flow ordering,
foreign-key aggregates, rollback, converters and idempotent seeds. `MigrationTestHelper` creates the
database from each committed historical JSON schema, runs the registered migration and validates
the result against the current export. Query-plan tests load synthetic data and run
`EXPLAIN QUERY PLAN`, asserting the intended indices are used without temporary sort B-trees.

The schema change procedure is documented in `CONTRIBUTING.md`. Schema JSON is generated by KSP and
must never be hand-edited.

## Security and failure model

The local database contains user file names, notes and study history. This foundation does not log
row data, does not seed implicitly, and does not permit release data loss as a recovery strategy.
Database-at-rest encryption and key management are separate platform work; the material `encrypted`
flag records object state but is not a claim that the SQLite file itself is encrypted.

Corrupt enum/scalar combinations fail mapping rather than fabricating a domain value. Migration
failure stops opening the database and preserves the file for recovery.

## Consequences

- Offline state has a single observable source of truth and deterministic write boundaries.
- Schema changes create reviewable JSON and executable migration obligations.
- Critical list/fold query plans are protected against accidental full scans and temporary sorts.
- Persistence mappings add deliberate duplication, but keep Android dependencies out of the domain.
- Development seed data is reproducible without risking production insertion.
